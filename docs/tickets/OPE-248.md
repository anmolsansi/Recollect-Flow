# OPE-248 — Recovery-capable Web Inbox and item review

## Local implementation status

The implementation is locally acceptance-complete as of 2026-08-08. This does
not claim production deployment or real-production-item acceptance.

## Delivered

- HttpOnly admin-session authentication with global `401`/`403` recovery.
- Cursor-paginated Inbox search with lifecycle/topic filters, structural
  snippets, debouncing, request cancellation, loading and failure states.
- Authoritative item detail including immutable source evidence, attachments,
  extraction coverage/errors, processing jobs, sync attempts, provenance,
  feedback, overrides and audit history.
- Optimistic derived-field edits, lifecycle actions, duplicate handling,
  privacy reprocessing, feedback, manual retry, soft deletion and restore.
- Explicit Notion-recreation eligibility shared by the API and UI.
- Owner overrides that survive enrichment and privacy reprocessing.
- Truthful read-only display of `Duplicate` and `Deleted` lifecycle states.

## Regression fixes completed

- Item edit/status/duplicate/privacy/delete/restore success is determined by
  `UPDATE ... RETURNING edit_version`, not aggregate D1 change counts inflated
  by FTS triggers.
- Superseded Notion sync attempts cannot be manually retried and do not expose
  an obsolete Retry control.
- Missing Notion projections expose a recovery action only when the server
  confirms that the item is eligible.
- The Worker test runtime pins the same `2026-08-01` compatibility date used by
  the project configuration.
