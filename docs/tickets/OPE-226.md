# OPE-226: Build daily digest and weekly review jobs

## Architecture decisions

1. Exact links point to the authenticated Web Inbox item-detail route configured
   by `WEB_INBOX_BASE_URL`.
2. Telegram timeout or malformed-success ambiguity is persisted as `unknown` and
   requires manual reconciliation. It is never automatically retried.
3. Periods are completed Asia/Kolkata calendar periods. Daily runs cover the
   previous day; weekly runs cover the previous Monday-to-Monday week.
4. Contradictions are not inferred by keywords. The weekly digest states that no
   explicit contradiction relation currently exists.

## Local implementation evidence

- Migration `0019_add_digest_jobs.sql` creates versioned runs, lease-protected
  deliveries and digest audit events.
- Daily selection includes eligible count, public topic groups, deterministic top
  items, processing failures and generic review actions.
- Weekly selection adds repeated themes, importance-70 Inbox review, 30-day
  dormant public projects and the 7-day warning before the 90-day archive point.
- Restricted content is projected to neutral labels and authenticated links.
  Every item is rechecked before delivery.
- AI wording is optional. Any provider/config/output failure keeps deterministic
  text deliverable and records a safe failure code.
- Telegram delivery validates configuration and response JSON, stores message
  IDs, honors 429 retry timing, uses bounded retries, and separates definite
  failure from ambiguous `unknown` state.
- Admin routes support generate, inspect, regenerate, review, queue, retry,
  reconcile and cancel actions with audit records.
- Scheduler routing keeps hourly work separate from daily and weekly digest crons.
