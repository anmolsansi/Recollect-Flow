# OPE-246: Implement reusable processing jobs, leases, retries, and recovery

## Context

RecollectFlow handles processing asynchronously (enrichment, sync, etc.). We need a robust leasing and retry mechanism for background jobs based on `processing_jobs` and `sync_attempts` tables.

## Requirements

1. Create a D1 migration (`migrations/0007_add_job_leases.sql`) to add `lease_owner` (TEXT) and `lease_expires_at` (TEXT) to both `processing_jobs` and `sync_attempts`. Add appropriate indices to query pending/stale jobs efficiently.
2. Implement `JobService` (`apps/worker-api/src/jobs/job.service.ts`) with:
   - `leaseJobs(limit, type, owner, ttlMinutes)`: Finds pending or stale jobs, updates status to `processing`, and sets lease fields.
   - `heartbeat(jobId, owner, ttlMinutes)`: Extends `lease_expires_at` for an active lease.
   - `completeJob(jobId)`: Marks job as `complete`, clears lease.
   - `failJob(jobId, errorCode, retryable)`: Marks job as `failed` (if terminal or max attempts reached) or `pending` (with exponential backoff `available_at`), increments attempts, clears lease.
3. Write unit tests for `JobService` covering lease acquisition (including stealing stale leases), completion, and retry backoff.
4. Update `CaptureService` or background cron handlers to utilize `JobService`.

## Files to inspect

- `docs/DATA_MODEL.md`
- `migrations/0001_initial.sql`
- `migrations/0005_update_hosted_ai_policy.sql`

## Definition of Done

- Migration is written and applies cleanly (`npm run db:migrate:local`).
- `JobService` is fully tested with Vitest.
- A failed job correctly calculates exponential backoff and becomes leasable again only after `available_at`.
