# OPE-225: Add D1 FTS5 indexing and knowledge search API

## Local acceptance mapping

1. `0016_add_item_search_fts.sql` creates `item_search_fts` over title, raw text,
   user note, summary, topics, project, people, and companies. Insert, update,
   soft-delete, restore, and hard-delete triggers keep it synchronized.
2. `GET /api/v1/search` requires the admin token and supports keyword or
   filter-only search with source, project, topic, lifecycle, processing,
   privacy, importance, and captured-date filters.
3. Keyword and filter-only modes use validated, fingerprinted keyset cursors.
   Rank, timestamp, item ID, query mode, and a snapshot cutoff prevent duplicate
   or omitted traversal across tied result sets.
4. Snippets are returned as bounded structural text segments. Clients never need
   to interpret FTS markers or inject search output as HTML.
5. Search is lexical D1-only and is exercised with the AI binding unavailable.
   Every owner-visible privacy level is covered through the authenticated route.
6. Malformed legacy topic JSON is ignored during indexing, response mapping, and
   topic filtering instead of causing a search failure.
7. `scripts/rebuild-item-search-index.sql` performs a transactional rebuild and
   returns canonical, indexed, missing, orphaned, and duplicate health counts.
