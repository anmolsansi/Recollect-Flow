# OPE-220: Design the Notion knowledge inbox and review workflow

## Context

Notion is used as the human review surface for RecollectFlow items. We need to formalize the Notion schema, views, and review states so we can build the Notion sync worker (OPE-221).

## Requirements

1. Review `docs/NOTION_INFORMATION_ARCHITECTURE.md` and ensure it maps precisely to our D1 schema (`items` and `attachments`).
2. Maintain the exact single-database JSON schema, property ownership, source
   types, retention behavior, and D1/Notion source-of-truth rules documented in
   `docs/NOTION_INFORMATION_ARCHITECTURE.md`.
3. Create and verify Inbox, Unprocessed, Worth Reviewing, Learning, Project
   Ideas, Active Projects, Archived, and Failed Syncs / Needs Attention views.
4. Verify the internal connection has access only to the Knowledge Inbox
   destination.
5. Update `NOTION_INFORMATION_ARCHITECTURE.md` if any discrepancies exist.

## Files to inspect

- `docs/NOTION_INFORMATION_ARCHITECTURE.md`
- `docs/DATA_MODEL.md`

## Definition of Done

- A concrete Notion Schema mapping (JSON) is documented.
- The Notion IA document perfectly aligns with D1 constraints.
- Required live views and the destination-only access boundary are verified.
- Approved by the Architect.
