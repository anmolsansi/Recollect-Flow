# OPE-227 — Quota tracking, provider circuit breakers, and zero-cost guards

Status: implementation in progress

## Goal

Keep RecollectFlow inside approved free-tier AI capacity while preserving capture, storage, search, review, and retry-safe background processing when hosted AI is unavailable.

## Frozen Phase 0 decisions

- ADR-028: quota enforcement is provider/operation/window specific. Only provider-published constrained dimensions are enforced; unpublished token quotas remain unset rather than being labeled unlimited.
- ADR-029: V1 may execute only explicitly approved free-tier provider/model combinations. Configuration alone cannot enable a paid endpoint/model.
- ADR-030: quota and circuit-breaker capacity deferrals return work to `pending` without consuming terminal retry allowance.

## Owner-approved OpenRouter baseline

Operational baseline dated 2026-08-09:

- shared account-wide free-model pool;
- 20 requests/minute;
- 50 requests/day for the ordinary free account;
- 1,000 requests/day only when the account has explicitly qualified through the documented lifetime-credit condition;
- no invented platform-wide input/output TPM or token/day limits;
- text and vision share the request pool;
- per-model context/output/modality limits are separate from account quota accounting;
- failed/retried free requests are treated conservatively as quota-consuming.

Provider limits are operational data and must be revalidated against authoritative provider documentation before production release/provider-policy changes.

## Capacity architecture

### Admission order

1. privacy/policy eligibility;
2. free-tier provider/model allowlist;
3. circuit-breaker availability;
4. quota-window availability;
5. atomic reservation across all applicable quota windows;
6. provider call;
7. usage reconciliation;
8. breaker success/failure update;
9. safe fallback only when policy and capacity both allow it.

### Quota state

Quota windows are keyed by provider + operation + reset window. A row keeps the applicable hard limits plus consumed/reserved counters. A single conditional D1 update must refuse the whole admission when any targeted window is exhausted so concurrent Workers cannot both consume the final available unit.

Reservations are durable and expire. Expiry is fail-safe capacity recovery for Workers that terminate after reserving but before reconciling.

### Circuit breaker

States: `closed`, `open`, `half_open`.

- qualifying provider failures increment the breaker;
- threshold crossing opens it;
- `open` blocks normal traffic until `next_probe_at`;
- only one half-open probe may hold the probe lease;
- successful probe closes/reset the breaker;
- failed probe reopens it with a new probe time.

Do not count privacy rejection, quota exhaustion, invalid application input, or owner-disabled providers as provider outages.

### Job deferral

Capacity failures use stable codes:

- `QUOTA_PAUSED`
- `PROVIDER_UNAVAILABLE`
- `NO_ELIGIBLE_PROVIDER`

Capacity deferral releases the job lease, restores `pending`, assigns deterministic `available_at`, and preserves the terminal retry allowance. Manual retry may make a job immediately eligible for leasing but may never bypass quota, privacy, free-tier, or breaker admission.

## Free-tier policy

OpenRouter V1 calls must use `openrouter/free` or a model identifier with an explicit `:free` variant. Unknown/non-free model identifiers fail closed before a network request.

Cloudflare Workers AI is separately constrained by its free allocation policy and must never rely on paid overage. Capacity configuration must keep the hard limit at or below the approved free allocation.

## Admin surface

`GET /api/v1/usage` is admin-only and returns safe metadata only:

- policy version;
- current quota windows and utilization;
- 70%/90%/hard thresholds;
- active/reserved/remaining capacity;
- breaker states and next probe times;
- deferred-job counts;
- last successful provider operation.

Never return prompts, raw content, credentials, provider responses, or token values.

## Implementation checkpoint

The branch now includes the durable `0020_add_ai_capacity_controls.sql` schema, UTC-aligned quota windows, atomic multi-window reservations, actual-usage reconciliation, abandoned-reservation cleanup, provider/operation circuit breakers, half-open probe leases, retry-preserving capacity deferral, zero-cost provider/model guards, policy-derived fallback plans, and the protected usage endpoint.

`AiProviderRegistry` is the mandatory non-mock execution boundary for enrichment, vision extraction, and optional digest wording. It reserves the worst-case bounded repair path before a hosted call and reconciles the actual request/input/output usage after success or failure. Policy fallbacks are taken only from `PolicyService.fallbackProviders`; OPE-227 does not approve any new privacy route.

Workerd-backed tests have been added for last-unit concurrency, reset boundaries, reservation reconciliation/expiry, breaker open/half-open/recovery, retry-preserving deferral, guarded registry calls, and usage endpoint authorization. Unit tests cover the free-tier allowlist and 70%/90%/hard utilization states. These tests are not marked accepted until the full branch quality gate passes.
